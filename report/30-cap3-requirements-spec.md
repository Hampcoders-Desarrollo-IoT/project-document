# Capítulo III: Requirements Specification

## 3.1. User Stories.

| Story ID | Título | Descripción | Criterios de Aceptación | Épica |
|----------|--------|-------------|------------------------|-------|
| EP-01 | Gestión de Acceso de Usuarios | Como usuario, quiero un sistema completo de acceso para registrarme, autenticarme y gestionar mis credenciales de manera segura según mi perfil específico (Propietario Individual, Empresa o Técnico). |
| US-01 | Registro de cuenta como Propietario Individual | Como propietario individual, quiero registrarme en la plataforma seleccionando el rol correspondiente, para acceder a los servicios de gestión eléctrica de mi vivienda o local. | **Escenario 1: Registro exitoso con datos válidos**<br>Dado que una persona no registrada accede al proceso de registro<br>Cuando selecciona el rol "Propietario Individual" y proporciona información personal válida (nombre, correo, contraseña)<br>Entonces el sistema crea una cuenta con el rol OWNER_INDIVIDUAL en estado PENDING_VERIFICATION<br>Y publica el evento `UserRegistered` hacia los contextos de Profiles y Subscriptions<br>Y notifica al usuario que se ha enviado un enlace de verificación a su correo.<br><br>**Escenario 2: Registro con correo ya registrado**<br>Dado que una persona intenta registrarse<br>Cuando ingresa un correo electrónico que ya está asociado a una cuenta activa<br>Entonces el sistema rechaza el registro<br>Y notifica que la dirección de correo ya está en uso. | EP-01 |
| US-02 | Registro de cuenta como Empresa | Como representante de una empresa, quiero registrarme en la plataforma indicando el tipo de cuenta empresarial, para gestionar el consumo eléctrico de mis instalaciones comerciales. | **Escenario 1: Registro exitoso de cuenta empresarial**<br>Dado que un representante empresarial no registrado accede al proceso de registro<br>Cuando selecciona el rol "Empresa" y proporciona información válida incluyendo nombre de la empresa<br>Entonces el sistema crea una cuenta con el rol COMPANY en estado PENDING_VERIFICATION<br>Y publica el evento `UserRegistered` hacia los contextos de Profiles y Subscriptions.<br><br>**Escenario 2: Registro con información de empresa incompleta**<br>Dado que un representante empresarial está en el proceso de registro<br>Cuando omite campos obligatorios como el nombre de la empresa<br>Entonces el sistema no completa el registro<br>Y notifica cuáles campos son requeridos. | EP-01 |
| US-03 | Registro de cuenta como Técnico | Como técnico eléctrico, quiero registrarme en la plataforma indicando mi perfil profesional, para ofrecer mis servicios a propietarios y empresas. | **Escenario 1: Registro exitoso como técnico**<br>Dado que un técnico eléctrico no registrado accede al proceso de registro<br>Cuando selecciona el rol "Técnico" y proporciona su información profesional válida<br>Entonces el sistema crea una cuenta con el rol TECHNICIAN en estado PENDING_VERIFICATION<br>Y publica el evento `UserRegistered`.<br><br>**Escenario 2: Registro fallido por contraseña débil**<br>Dado que un técnico está completando el formulario de registro<br>Cuando ingresa una contraseña que no cumple con los requisitos mínimos de seguridad<br>Entonces el sistema rechaza el registro<br>Y notifica los requisitos que no se cumplen. | EP-01 |
| US-04 | Autenticación de usuario registrado | Como usuario registrado y verificado, quiero autenticarme en la plataforma con mis credenciales, para acceder a las funcionalidades según mi rol y plan de suscripción. | **Escenario 1: Autenticación exitosa**<br>Dado que un usuario con cuenta en estado ACTIVE intenta autenticarse<br>Cuando proporciona credenciales válidas (correo y contraseña)<br>Entonces el sistema valida las credenciales, genera un token de sesión JWT<br>Y publica el evento `UserAuthenticated`<br>Y concede acceso a las funcionalidades correspondientes a su rol y plan de suscripción.<br><br>**Escenario 2: Autenticación fallida por credenciales inválidas**<br>Dado que un usuario intenta autenticarse<br>Cuando proporciona un correo o contraseña incorrectos<br>Entonces el sistema deniega el acceso<br>Y notifica que las credenciales son inválidas sin revelar cuál campo es incorrecto.<br><br>**Escenario 3: Intento de acceso con cuenta suspendida**<br>Dado que un usuario intenta autenticarse<br>Cuando su cuenta se encuentra en estado SUSPENDED<br>Entonces el sistema deniega el acceso<br>Y notifica que la cuenta está suspendida e indica cómo regularizar la situación. | EP-01 |
| US-05 | Cierre de sesión seguro | Como usuario autenticado, quiero cerrar mi sesión de forma segura, para proteger mi cuenta cuando termine de usar la plataforma. | **Escenario 1: Cierre de sesión voluntario**<br>Dado que un usuario está autenticado en la plataforma<br>Cuando solicita cerrar su sesión<br>Entonces el sistema invalida el token de sesión activo<br>Y deniega el acceso a cualquier recurso protegido usando el token invalidado. | EP-01 |
| EP-02 | Experiencia de Registro y Verificación | Como usuario, quiero recibir retroalimentación clara durante el proceso de registro y verificar mi identidad, para completar el onboarding sin fricciones. |
| US-06 | Verificación de cuenta por correo electrónico | Como usuario recién registrado, quiero verificar mi cuenta a través de un enlace enviado a mi correo, para confirmar mi identidad y activar el acceso completo. | **Escenario 1: Verificación exitosa**<br>Dado que un usuario se ha registrado exitosamente y recibe el correo de verificación<br>Cuando utiliza el enlace único de verificación dentro del período de validez<br>Entonces el sistema actualiza el estado de la cuenta de PENDING_VERIFICATION a ACTIVE<br>Y notifica al usuario que la verificación fue exitosa.<br><br>**Escenario 2: Enlace de verificación expirado**<br>Dado que un usuario intenta verificar su cuenta<br>Cuando el enlace de verificación ya ha expirado<br>Entonces el sistema rechaza la solicitud<br>Y ofrece la opción de reenviar un nuevo enlace de verificación. | EP-02 |
| US-07 | Recuperación de contraseña | Como usuario registrado que olvidó su contraseña, quiero iniciar un proceso de recuperación, para volver a acceder a mi cuenta de manera segura. | **Escenario 1: Solicitud de recuperación con correo válido**<br>Dado que un usuario se encuentra en el proceso de recuperación de contraseña<br>Cuando ingresa el correo electrónico asociado a su cuenta activa<br>Entonces el sistema genera un token de recuperación con tiempo de expiración definido<br>Y envía las instrucciones de recuperación al correo proporcionado.<br><br>**Escenario 2: Restablecimiento exitoso de contraseña**<br>Dado que un usuario sigue el enlace de restablecimiento dentro del período de validez<br>Cuando ingresa y confirma una nueva contraseña que cumple los requisitos de seguridad<br>Entonces el sistema actualiza la contraseña encriptada<br>Y elimina el token de recuperación utilizado<br>Y notifica al usuario que el cambio fue exitoso.<br><br>**Escenario 3: Token de recuperación expirado**<br>Dado que un usuario intenta usar el enlace de recuperación<br>Cuando el token ha superado su tiempo de expiración<br>Entonces el sistema rechaza la solicitud<br>Y notifica que el enlace ha expirado. | EP-02 |
| EP-03 | Personalización y Seguridad de la Cuenta | Como usuario, quiero tener control sobre la seguridad y configuración de mi cuenta, para proteger mi información y adaptarla a mis necesidades. |
| US-08 | Visualización del perfil de propietario | Como propietario autenticado, quiero visualizar mi perfil personal, para revisar mi información almacenada y mis preferencias de notificación. | **Escenario 1: Acceso exitoso al perfil**<br>Dado que un propietario está autenticado<br>Cuando solicita acceder a su información de perfil<br>Entonces el sistema retorna la información personal registrada (nombre, correo, teléfono) sin exponer datos sensibles como contraseñas<br>Y muestra las preferencias de notificación configuradas. | EP-03 |
| US-09 | Edición del perfil de propietario | Como propietario autenticado, quiero editar mi información personal y preferencias, para mantener mi perfil actualizado. | **Escenario 1: Actualización exitosa de información personal**<br>Dado que un propietario está autenticado<br>Cuando modifica campos válidos de su perfil (nombre, teléfono, preferencias) y confirma los cambios<br>Entonces el sistema valida y almacena la información actualizada<br>Y confirma que los cambios fueron guardados exitosamente.<br><br>**Escenario 2: Edición con datos inválidos**<br>Dado que un propietario intenta actualizar su perfil<br>Cuando proporciona datos que no cumplen las reglas de validación<br>Entonces el sistema rechaza la actualización<br>Y retorna los errores de validación por campo. | EP-03 |
| US-10 | Visualización del perfil de técnico | Como técnico autenticado, quiero visualizar mi perfil profesional completo, para revisar cómo se presenta mi información, especialidades y zona de cobertura a los clientes. | **Escenario 1: Acceso al perfil profesional**<br>Dado que un técnico está autenticado<br>Cuando solicita acceder a su perfil profesional<br>Entonces el sistema retorna su información profesional incluyendo especialidades, zona de cobertura geográfica, certificación IoT (si aplica) y portafolio de trabajos. | EP-03 |
| US-11 | Edición del perfil de técnico | Como técnico autenticado, quiero editar mi información profesional, especialidades y zona de cobertura, para mantener mi perfil actualizado y atractivo para los clientes. | **Escenario 1: Edición exitosa de información profesional**<br>Dado que un técnico está autenticado<br>Cuando modifica su descripción, información de contacto, especialidades o zona de cobertura y guarda los cambios<br>Entonces el sistema almacena los cambios<br>Y publica el evento `TechnicianDataUpdated` para que el contexto de Planning BC recalcule el matching si cambió la zona de cobertura.<br><br>**Escenario 2: Gestión de portafolio de trabajos**<br>Dado que un técnico está editando su perfil<br>Cuando añade un trabajo al portafolio con descripción e imágenes de evidencia<br>Entonces el sistema almacena el trabajo en el portafolio<br>Y lo hace disponible en su perfil profesional. | EP-03 |
| US-12 | Configuración de preferencias de notificación | Como usuario autenticado, quiero configurar mis preferencias de notificaciones, para recibir únicamente las alertas relevantes sin ser saturado de mensajes. | **Escenario 1: Actualización de preferencias de notificación**<br>Dado que un usuario está autenticado<br>Cuando ajusta sus preferencias de notificación (tipos de eventos, canales como email o push)<br>Entonces el sistema almacena las preferencias<br>Y las notificaciones futuras respetan la configuración seleccionada. | EP-03 |
| EP-04 | Gestión de Catálogo de Servicios del Técnico | Como técnico, quiero administrar mi catálogo de servicios con sus recetas de componentes, para mantener actualizada mi oferta y participar en el matching automático. |
| US-13 | Creación de recipe de servicio en catálogo | Como técnico con suscripción Premium activa, quiero crear un nuevo recipe de servicio en mi catálogo especificando la categoría, componentes necesarios y precio, para que el sistema me asigne solicitudes de esa categoría automáticamente. | **Escenario 1: Creación exitosa de recipe**<br>Dado que un técnico con plan Premium está autenticado y su catálogo existe<br>Cuando proporciona datos válidos para un nuevo recipe (categoría de servicio, lista de componentes con cantidades, precio base y duración estimada)<br>Entonces el sistema crea el recipe en estado activo<br>Y publica el evento `ServiceRecipeCreated`<br>Y si el catálogo estaba en estado EMPTY, transiciona a ACTIVE.<br><br>**Escenario 2: Técnico sin suscripción Premium intenta crear recipe**<br>Dado que un técnico con plan FREE intenta crear un recipe<br>Cuando envía la solicitud de creación<br>Entonces el sistema rechaza la operación<br>Y publica el evento `ServiceCreationDeniedDueToSubscription`. | EP-04 |
| US-14 | Modificación de recipe de servicio | Como técnico Premium autenticado, quiero editar los recipes existentes de mi catálogo (descripción, componentes, precio), para mantener actualizada mi oferta de servicios. | **Escenario 1: Actualización exitosa de recipe sin servicios activos**<br>Dado que un técnico está autenticado y selecciona un recipe activo sin servicios actualmente asignados<br>Cuando modifica el precio, lista de componentes o duración estimada<br>Entonces el sistema actualiza el recipe<br>Y publica el evento `ServiceRecipeUpdated`.<br><br>**Escenario 2: Modificación de recipe con servicios asignados en curso**<br>Dado que un técnico intenta modificar el precio de un recipe que tiene servicios en estado SCHEDULED<br>Cuando el incremento de precio supera el 20% del precio original<br>Entonces el sistema rechaza el cambio de precio<br>Y notifica al técnico la restricción. | EP-04 |
| US-15 | Desactivación de recipe de servicio | Como técnico Premium autenticado, quiero desactivar un recipe de mi catálogo cuando ya no ofrezco ese servicio, para evitar que el sistema me asigne solicitudes que no puedo atender. | **Escenario 1: Desactivación exitosa de recipe**<br>Dado que un técnico está autenticado y selecciona un recipe activo<br>Cuando solicita su desactivación<br>Entonces el sistema cambia el estado del recipe a INACTIVE<br>Y publica el evento `ServiceRecipeDeactivated`<br>Y si era el último recipe activo, el catálogo transiciona a INACTIVE.<br><br>**Escenario 2: El recipe desactivado no afecta servicios asignados**<br>Dado que un recipe es desactivado<br>Cuando existen servicios en estado SCHEDULED que usan ese recipe<br>Entonces el sistema mantiene esos servicios en su estado actual usando el RecipeSnapshot capturado al momento de la asignación. | EP-04 |
| US-16 | Reactivación de recipe de servicio | Como técnico Premium autenticado, quiero reactivar un recipe previamente desactivado, para volver a ofrecerlo cuando esté disponible para atenderlo. | **Escenario 1: Reactivación exitosa de recipe**<br>Dado que un técnico está autenticado y selecciona un recipe en estado INACTIVE<br>Cuando solicita su reactivación<br>Entonces el sistema cambia el estado del recipe a ACTIVE<br>Y publica el evento `ServiceRecipeReactivated`<br>Y si el catálogo estaba en estado INACTIVE, transiciona a ACTIVE. | EP-04 |
| US-17 | Establecimiento de precios diferenciados por zona | Como técnico Premium autenticado, quiero establecer precios diferenciados para mis servicios según la zona de cobertura, para tener una estructura tarifaria adaptada a mi área de operación. | **Escenario 1: Definición de precio base de servicio**<br>Dado que un técnico está creando o editando un recipe<br>Cuando establece un precio base para el servicio<br>Entonces el sistema almacena el precio y lo incluye en los resultados de búsqueda de categorías disponibles para propietarios.<br><br>**Escenario 2: Precio diferenciado por zona de cobertura**<br>Dado que un técnico ha definido múltiples zonas de cobertura<br>Cuando edita un recipe y asigna un precio diferente a una zona específica<br>Entonces el sistema almacena el precio diferenciado<br>Y el algoritmo de matching considera el precio correspondiente a la zona de la propiedad solicitante. | EP-04 |
| EP-05 | Gestión de Agenda y Disponibilidad del Técnico | Como técnico, quiero configurar y gestionar mi disponibilidad semanal, bloqueos de horario y parámetros de traslado, para que el sistema me asigne trabajos de forma óptima. |
| US-18 | Configuración de horarios de trabajo semanales | Como técnico Premium autenticado, quiero configurar mis horarios de trabajo por día de la semana, para que el sistema me asigne solicitudes únicamente dentro de mis horarios laborales disponibles. | **Escenario 1: Establecer disponibilidad semanal**<br>Dado que un técnico está autenticado<br>Cuando define sus horas de inicio y fin de trabajo para cada día de la semana<br>Entonces el sistema almacena la disponibilidad semanal del técnico<br>Y el algoritmo de matching la utiliza como criterio para la asignación automática de servicios.<br><br>**Escenario 2: Actualización de horario existente**<br>Dado que un técnico tiene un horario de trabajo configurado<br>Cuando modifica las horas de un día laboral y guarda los cambios<br>Entonces el sistema actualiza el horario estándar<br>Y las solicitudes pendientes de matching recalculan la disponibilidad. | EP-05 |
| US-19 | Bloqueo de fechas y horarios específicos | Como técnico Premium autenticado, quiero bloquear fechas o rangos de horas específicos en mi agenda, para evitar que el sistema me asigne trabajos durante compromisos personales o vacaciones. | **Escenario 1: Bloqueo exitoso de período**<br>Dado que un técnico está autenticado<br>Cuando selecciona una fecha o rango de horas y lo registra como no disponible<br>Entonces el sistema almacena el bloqueo<br>Y no asigna servicios al técnico durante ese período.<br><br>**Escenario 2: Eliminación de bloqueo**<br>Dado que un técnico tiene un bloqueo registrado<br>Cuando solicita eliminarlo<br>Entonces el sistema elimina el bloqueo<br>Y ese período vuelve a estar disponible para el matching automático. | EP-05 |
| US-20 | Configuración de tiempo de traslado entre servicios | Como técnico Premium autenticado, quiero configurar el tiempo promedio que necesito para trasladarme entre ubicaciones, para que el sistema considere estos intervalos al asignarme trabajos consecutivos. | **Escenario 1: Configuración exitosa de buffer de traslado**<br>Dado que un técnico está autenticado<br>Cuando define un tiempo promedio de traslado en minutos<br>Entonces el sistema almacena el buffer de traslado<br>Y el algoritmo de matching incluye este intervalo entre servicios consecutivos para evitar solapamientos. | EP-05 |
| US-21 | Visualización de agenda de trabajos asignados | Como técnico Premium autenticado, quiero consultar todos los trabajos que el sistema me ha asignado automáticamente, para planificar mi jornada y conocer mi carga de trabajo. | **Escenario 1: Consulta de trabajos asignados**<br>Dado que un técnico está autenticado y tiene trabajos asignados<br>Cuando consulta su agenda<br>Entonces el sistema retorna la lista de servicios asignados con sus detalles (fecha, categoría de servicio, ubicación de la propiedad y estado).<br><br>**Escenario 2: Agenda sin trabajos asignados**<br>Dado que un técnico está autenticado y no tiene trabajos asignados en el período consultado<br>Cuando consulta su agenda<br>Entonces el sistema retorna una lista vacía. | EP-05 |
| EP-06 | Contratación de Servicios Eléctricos | Como propietario o empresa, quiero solicitar servicios eléctricos mediante un proceso guiado paso a paso, para resolver mis necesidades eléctricas de forma estructurada. |
| US-22 | Inicio del proceso de solicitud de servicio | Como propietario autenticado, quiero iniciar el proceso de solicitud de un servicio eléctrico para que el sistema valide mi plan antes de continuar, para no desperdiciar tiempo si he alcanzado mi límite de solicitudes. | **Escenario 1: Propietario FREE dentro del límite de solicitudes**<br>Dado que un propietario con plan FREE está autenticado y ha creado menos de 2 solicitudes en el ciclo actual<br>Cuando inicia el asistente de solicitud de servicio<br>Entonces el sistema crea una solicitud en estado DRAFT<br>Y publica el evento `ServiceRequestInitiated`.<br><br>**Escenario 2: Propietario FREE en límite de solicitudes**<br>Dado que un propietario con plan FREE ha alcanzado su límite mensual de solicitudes<br>Cuando intenta iniciar una nueva solicitud<br>Entonces el sistema rechaza la acción<br>Y publica el evento `ServiceRequestLimitReached`<br>Y notifica al propietario que ha alcanzado su límite e informa sobre el plan Premium.<br><br>**Escenario 3: Propietario Premium sin límite**<br>Dado que un propietario con plan PREMIUM_INDIVIDUAL está autenticado<br>Cuando inicia el asistente de solicitud de servicio<br>Entonces el sistema crea una solicitud en estado DRAFT sin restricción de límite. | EP-06 |
| US-23 | Selección de propiedad para el servicio | Como propietario con múltiples propiedades registradas, quiero seleccionar la propiedad específica donde necesito el servicio, para que el sistema use su ubicación en el proceso de matching. | **Escenario 1: Selección exitosa de propiedad**<br>Dado que un propietario tiene una solicitud en estado DRAFT y tiene propiedades registradas<br>Cuando selecciona una de sus propiedades registradas<br>Entonces el sistema asocia la geolocalización de la propiedad a la solicitud<br>Y la solicitud transiciona al estado PROPERTY_SELECTED<br>Y publica el evento `PropertySelectedForRequest`.<br><br>**Escenario 2: Sin propiedades registradas**<br>Dado que un propietario inicia una solicitud pero no tiene propiedades registradas<br>Cuando llega al paso de selección de propiedad<br>Entonces el sistema notifica que debe registrar al menos una propiedad antes de continuar. | EP-06 |
| US-24 | Selección de categoría de servicio disponible | Como propietario con una solicitud en proceso, quiero ver las categorías de servicio disponibles en la zona de mi propiedad, para seleccionar la que se ajusta a mi necesidad. | **Escenario 1: Categorías disponibles en la zona**<br>Dado que un propietario tiene una solicitud en estado PROPERTY_SELECTED<br>Cuando consulta las categorías disponibles<br>Entonces el sistema retorna las categorías de servicio para las que existen técnicos con zona de cobertura activa en la ubicación de la propiedad, mostrando rango de precios y duración estimada.<br><br>**Escenario 2: Sin cobertura en la zona**<br>Dado que un propietario consulta categorías disponibles<br>Cuando ningún técnico activo tiene cobertura en la zona de la propiedad<br>Entonces el sistema retorna una lista vacía e indica que no hay cobertura disponible en esa ubicación.<br><br>**Escenario 3: Selección de categoría**<br>Dado que el propietario ve categorías disponibles<br>Cuando selecciona una categoría de servicio<br>Entonces la solicitud transiciona al estado CATEGORY_SELECTED<br>Y publica el evento `ServiceCategorySelected`. | EP-06 |
| US-25 | Descripción detallada del problema eléctrico | Como propietario con una solicitud en proceso, quiero añadir una descripción detallada de mi problema eléctrico y mis datos de recibo, para que el técnico llegue con contexto previo. | **Escenario 1: Adición de detalles del servicio**<br>Dado que un propietario tiene una solicitud en estado CATEGORY_SELECTED<br>Cuando proporciona la descripción del problema y los datos de recibo eléctrico (consumo kWh, monto, período de facturación)<br>Entonces el sistema almacena los detalles en la solicitud<br>Y la solicitud transiciona al estado READY_TO_CONFIRM<br>Y publica el evento `ServiceDetailsAdded`.<br><br>**Escenario 2: Datos de recibo incompletos**<br>Dado que un propietario está añadiendo detalles de su solicitud<br>Cuando omite campos obligatorios del recibo eléctrico<br>Entonces el sistema no permite avanzar al estado READY_TO_CONFIRM<br>Y notifica los campos requeridos. | EP-06 |
| US-26 | Confirmación de solicitud de servicio | Como propietario con una solicitud lista para confirmar, quiero confirmar la solicitud de servicio, para que el sistema inicie el proceso de matching y asignación de técnico. | **Escenario 1: Confirmación exitosa de solicitud estándar**<br>Dado que un propietario tiene una solicitud en estado READY_TO_CONFIRM<br>Cuando confirma la solicitud sin marcarla como prioritaria<br>Entonces el sistema cambia el estado a PENDING_ASSIGNMENT<br>Y publica el evento `ServiceRequestCreated`<br>Y encola la solicitud en la cola normal FIFO para el proceso de matching.<br><br>**Escenario 2: Confirmación de solicitud prioritaria (solo plan Premium)**<br>Dado que un propietario con plan PREMIUM_INDIVIDUAL tiene una solicitud en estado READY_TO_CONFIRM<br>Cuando confirma la solicitud marcándola como prioritaria<br>Entonces el sistema cambia el estado a PENDING_ASSIGNMENT con la bandera `isPriority = true`<br>Y encola la solicitud en la cola de prioridad para ser procesada antes que las normales.<br><br>**Escenario 3: Propietario FREE intenta marcar como prioritaria**<br>Dado que un propietario con plan FREE intenta confirmar una solicitud como prioritaria<br>Cuando envía la confirmación<br>Entonces el sistema rechaza la operación<br>Y notifica que la opción de prioridad es exclusiva del plan Premium. | EP-06 |
